## 2. 真分歧 —— 两边都说得通,需要定

### 2.1 平台「强势日」的尺子 【最重要 —— 已实测,见下】

```python
# 他 weekly_engine.py:platform_state
strong = np.flatnonzero(rps.ge(cfg['rps_strong']).to_numpy())   # rps = ranks[50],即 RPS50 ≥ 90
# 我 consolidation_screener.py:208
RPS60 = CL.pct_change(60).rank(axis=1, pct=True) * 100
return ..., (RPS60 > 90).to_numpy(), ...
```

**这不是阈值之争,是定义之争。** 强势日 `ts` 是**调整段的起点**;`ts` 一动,
深度 / 缩量比的窗口 `[ts, t]`、收敛比的分母窗口 `[ts−60, ts]` **全部整体平移**。
他 `run_weekly.py` 里还硬挡了 RPS60:

```python
if cfg['rps_periods']!=list(PERIODS): raise ValueError('本工具固定使用RPS50、120、250，不允许RPS60')
```

#### 实测结果(脚本 `strongday_rps50_vs_rps60.py`,同一张面板、同一套 legacy 阈值,只换强势日)

**先说我自己在这个脚本上犯的两个错 —— 都是恒等断言(锚点 D)抓出来的,两版结果已作废:**

1. 第一版 RPS50 腿写了 `fill_method=None`,而 RPS60 腿走 pandas 默认的 `'pad'`,
   两条腿缺失处理不同,比较不成立(该版给出池内 12 只);
2. 第二版补了 `fill_method`,却把 RPS 挪到剔除 `510300` **之后**才算 ——
   RPS 是 `axis=1` 横截面分位,少一列全变,自算 RPS60 差 358 点
   (1,217,240 vs 1,217,598),断言当场不过。

第三版锚点 A/B/D 全过(`1,217,598` 精确复现)。以下是第三版:

| | RPS60 > 90(我) | RPS50 ≥ 90(他) | 差 |
|---|---|---|---|
| 强势日点数(全历史) | 1,217,598 | 1,222,179 | +0.4% |
| 三条全中(全历史) | 1,414,428 | 1,409,206 | **−0.37%** |
| 突破买点(全历史) | 31,902 | 28,346 | −11.1% |
| **2026-08-28 全市场平台观察** | **137** | **154** | +12.4% |
| **2026-08-28 池内(662)平台观察** | **19** | **15** | −4 |

**两条重要结论:**

**(1) 尺子解释不了你的 2 只。**

```
19 只(RPS60,我)  →  15 只(RPS50,同一张面板)   ← 尺子只解释这一段
15 只            →   2 只(你)                  ← 剩下的不是尺子
```

所以我上封信列的两个候选原因现在分开了:**(a) 尺子占 19→15,(b) 你的 5 年面板
起点 + 严格拒缺失占 15→2。** 后者是主因。

**(2) 全市场几乎一样,个股分歧很大。** 全历史三条全中只差 0.37%,
但 662 池内 RPS60 出 19、RPS50 出 15、**只有 9 只重合**(并集 25),一致率 **9/25 = 36%**。

**机制与我原先的猜测相反。** 我以为 RPS50 会让强势日更密、`[ts,t]` 更短、
卡在「调整天数 < 15」。实测:RPS50 的最近强势日几乎都**更早**
(301275 从 18 天变 149 天),窗口**更长**,三项在更长区间上被量而冲破阈值 ——

```
去向汇总(RPS60 腿命中的 19 只在 RPS50 腿上):
  同样命中                9
  三项阈值不过            9
  RPS50 腿近250日无强势日  1
  卡在「调整天数<15」      0      ← 我猜的那条,一个都没有
```

**【更正】关于宇通锚点,我先报了一个错的结论,现更正:**

我一度报「宇通锚点没过(实测 55 天 vs 期望 42 天),该行作废」。**锚点没有不过,
是我量错了对象。** 第八七/一五五节记的 42 天,一直是**窗口
`[2023-10-17, 2024-01-09]` 之内**的三条全中天数 —— `platform_pivot.py:B1(e-2)`
就是这么写的,而且那段代码**还顺带印出「2023-2024 全年共 N 天」作参考**。
我这次数的正是那个全年参考数(55 天),然后拿它去对窗口锚点、宣布作废。

**这是第一五五节那个坑的第二次**(上次是漏抄第三个数,这次是没看清窗口)。
脚本已改回窗口口径。**RPS60 腿的宇通锚点成立,42 天没问题。**
RPS50 尺子下的窗口内天数由第一六七节的正式重跑给出。

### 2.2 「突破」的两处不同

他的读法是「昨天平台成立,今天收盘破了它」;我的读法是「今天仍在平台里,

### 2.3 缺失语义:他一律拒,我按用户规则 5 ffill

他的做法是硬拒:
- `rolling(250, min_periods=250)` —— 窗口里一个 NaN 就 NaN;
- 平台区间 `[ts,t]` 任一 OHLCV 为 NaN → 「数据不足:平台区间行情有缺口」;
- 基期 60 日必须 `notna().sum() == 60`,否则「数据不足」。

我这边按项目硬规则「**退市股按最后有效价 ffill 参与,绝不剔除**」。
**这条我不要求他改**(他的做法在他的用途下更保守),但结论是:
**两边的「数据不足」不可直接对比**,89 vs 110 的差额里有一部分是这个,不只是面板起点。

## 3. 我认为值得他改的

### 3.1 `history_years: 5` 对「当日观察」够用,但**不能用它复算历史**

平台需要:强势日回看 250 + 基期 60 + MA100 的 100 行。5 年 ≈ 1,215 个交易日,
**在 2026-08-28 这一天完全够**。但模板里的「首次触发日期 / 连续确认天数」是**历史量**,
一旦回溯到窗口起点附近就会系统性少信号。

**他已经把最坏情况挡住了**,这点做得对:

```python
if start == 0 or pd.isna(signal.iloc[start - 1]):
    return None, None, '历史起点待核对'
```

**建议**(小改):在 `metadata` 里加一行
`max_lookback_required` vs `calendar_rows`,让读表的人一眼看到余量还剩多少。

### 3.2 `financial_snapshot` 在 `eff > date` 时丢掉整只股票,而不是回退上一期

```python
if pd.isna(eff) or eff > date:
    continue          # ← 整只股票没有任何财务,而不是退回上一期已披露的报告
```

触发条件很窄(`publish_date < date` 已过滤在前),但**一旦触发就是「有财务却报缺失」**。
建议改成回退到 `g.index[-2]`。

### 3.3 冲突期的排除粒度过粗

```python
conflict = f.groupby(['code','report_date'])[numeric].nunique().gt(1).any(axis=1)
```

五个数值列里**任何一列**冲突,整个报告期被丢。`revenue` 的一次修订会连带丢掉 `roe`。
保守是对的,但 `audit` 里现在只给了个数(`conflicting_periods_excluded`),
**建议同时给出被排除的 code 列表**,否则没法判断丢掉的是不是关键股票。

### 3.4 `data_state` 分不清「次新股本来没 250 天」和「中间停牌」

```python
'250日价格窗口不足或有缺口' if r['recovery'] is None else ''
```

这两种缺失的处置完全不同(前者等时间,后者要查数据)。**建议拆成两条。**
我这边在 662 池上量到:上市天数 `[120,250)` 的有 **25 只**,`≥250` 的 **593 只**,
「面板无此股」**44 只** —— 这三类现在在他的输出里混在同一句话里。

### 3.5 平台三项阈值本身没有单元测试

`test_platform_cannot_use_current_high_as_breakout_boundary` 为了隔离突破不变量,
把 `platform_atr_max` 放宽到 100(他写了注释说明,做法可以接受)。
**但这意味着 depth / vol / atr 三个数值本身没有任何测试钉住。**
建议补一个用固定数列把这三个数算到小数点后几位的测试 ——
我第一五五节就是在这里栽的(float32 边界把「打平」误判成突破,虚增留出段约 4pp)。

### 3.6 `platform_state` 只在 `t` 与 `t−1` 求值

所以「平台明细」页无法回放历史。当日观察够用;若以后要出平台的连续天数,这里要改。
