# 价格信号 + 平台信号 + 质量因子 —— 监控模板使用说明书 v1.0

**配套文件**:`signal_template_blank_v1.0.xlsx`(空白模板)
**生成脚本**:`rps_pool_study/signal_template_blank.py`
**日期**:2026-08-28

---

## 0. 这个模板解决什么问题

**一句话:把「口径」「数据」「自检」三件事绑在同一个文件里。**

之前两边各自出表,对不上时要花很久才能定位到底是**口径不同**还是**实现有错**。
本模板做三件事:

1. **字段字典页**把每个字段的计算口径写死,并标出它是**正式 / 已实现 / 研究 / 展示**四级中的哪一级;
2. **检查页用真公式自动勾稽**,粘完数据立刻能看出数量对不对;
3. **恒等式自检页**逐条检查值域恒等式 —— **这一页才是真正能抓到错的地方。**

**已在 13,938 行真实数据上验证:15 条恒等式全部 0 违例。**

## 2. 填表顺序

### 第一步:先填「数据锚点」页 —— 不要跳过

```
面板交易日数 / 面板股票只数 / 面板首日 / 面板末日
规则文件与版本 / 规则哈希 / 数据快照哈希
复权方式(以及成交量是否随之调整)
RPS 横截面池(池内只数、是否逐日剔除 ST/停牌/零成交)
财务生效规则
```

**为什么这页是第一位的**:规则可追溯之外,**数据也必须可追溯**。
同一套规则在不同数据快照上会出不同结果 —— 面板末日差 12 个交易日,
就足以让「最近一次强势日」落在不同的位置,进而改变平台三值。
两边核对时,**先看这一页对不对得上,再看数据**,能省掉大量无效排查。

### 第二步:把数据粘进「全部清单」第 3 行起

**列顺序不要动。** 第 1 行是分组色带,第 2 行是列名,第 3 行起是数据。

### 第三步:看「检查」页,「差异」列必须全 0

| 勾稽项 | 恒等关系 |
|---|---|
| 统一信号=1 | **必须等于** 强确认 + 标准确认 |
| 平台信号三档合计 | **必须等于** 总行数 |
| 质量四档合计 | **必须等于** 总行数 |
| 周线五态合计 | **必须等于** 总行数 |
| 周线多头排列为真 | **必须等于** 五态 = 多头趋势 的行数 |

### 第四步:看「恒等式自检」页,15 条违例数必须全 0

这一页是模板的核心。**只数「字段有没有」查不出任何值错误,恒等式才能。**

## 3. 十五条恒等式,以及每一条在防什么

| # | 恒等式 | 防的是 |
|---|---|---|
| 1 | 统一信号=1 ⟺ 信号类型∈{强确认,标准确认} | 两列各自生成时脱钩 |
| 2 | 强确认 ⟹ RPS60 ≥ 90 | 分档门槛写错 |
| 3 | 标准确认 ⟹ 80 ≤ RPS60 < 90 | 边界取等号取反 |
| 4 | 观察级 ⟹ RPS60 < 80 | 同上 |
| 5 | 信号类型≠无信号 ⟹ 三条件全中 | 观察条件与分档不一致 |
| 6 | 触发状态=新触发 ⟺ 连续确认天数=1 | 状态机实现错误 |
| 7 | 触发状态=未触发 ⟺ 连续确认天数=0 | 同上 |
| 8 | **连续>0 ⟹ 首次触发日期非空且 ≤ 观察日** | **前视 —— 首次触发日晚于观察日就是穿越** |
| 9 | 周线多头排列=TRUE ⟺ 五态=多头趋势 | 正式二元字段与展示标签不自洽 |
| 10 | 平台深度 ∈ [0, 1) | 高低点取反、除零 |
| 11 | 平台信号≠无 ⟹ 平台三值齐全 | 判定与取值脱钩 |
| 12 | 质量分 ∈ [0,1] 且与分层自洽 | 切点写反 |
| 13 | **距一年高点价格差 ≤ 0** | 窗口不含当日 → 现价高于「最高」 |
| 14 | MA20持续度 ∈ [0, 1] | 计数除以错误的分母 |
| 15 | RPS60 / RPS250 ∈ [0, 100] | 分位没乘 100 或算成小数 |

第 8 和第 13 条是**直接查前视**的,建议永远保留。

## 4. 四级验证状态(建议取代散乱标签)

| 级别 | 含义 | 能不能进信号 |
|---|---|---|
| **正式** | 已通过样本外 + 随机对照 | 能 |
| **已实现** | 口径冻结、实现完成,但未做样本外或未做对照 | **不能** |
| **研究** | WATCHLIST,只作事件池与状态标记 | **不能** |
| **展示** | 仅为读表方便而加的分层/标签 | **不能** |

**建议不要超过四级。** 标签一多(「已使用」「机制初步支持」「机制已核对」「待优化」
「待执行校正」……),读表的人分不清哪个真过了检验,标注本身就失去意义。

**同一字段在不同口径下结论相反时必须写明。** 例如某个价格信号在
「概率口径」(未来 N 日涨幅达标的概率)下通过,在「组合口径」
(等权持有并对同市值同行业随机对照)下不通过 —— 只写「已验证」会让后面的人误以为能用。

## 5. 配色规则

| 列 | 配色 |
|---|---|
| 信号类型 | 强确认=粉 · 标准确认=黄 · 观察级=蓝 · 无信号=白 |
| 平台信号 | 平台突破(研究)=橙 · 平台观察=浅黄 · 无平台信号=白 |
| 案例展示分层_质量 | 高=绿 · 中=白 · 低=粉 · 缺失=灰 |
| 案例辅助标签_周线五态 | 多头趋势=绿 · 突破启动=橙 · 回踩修复=黄 · 均线蓄势=蓝 · 弱势结构=粉 |
| 触发状态 | 新触发=绿加粗 · 持续=蓝 · 未触发=白 |

**一律用静态填充,不要用条件格式。**
条件格式在 WPS 里会出现**白字白底、单元格看着是空的**的情况 —— 踩过一次,不再用。

## 6. 字段口径(冻结部分)

### 6.1 价格四档(X01 v1.0)

```
三个观察条件:距一年低点涨幅 ≥ 40%
              近120日收益 ≥ 10%
              近120日站上MA20比例 ≥ 55%

三条件全中 且 RPS60 <  80  → 观察级      统一信号 = 0
三条件全中 且 RPS60 ≥  80  → 标准确认    统一信号 = 1
三条件全中 且 RPS60 ≥  90  → 强确认      统一信号 = 1
未全中                      → 无信号      统一信号 = 0
必需价格字段缺失            → 不具备资格,不得回退默认值
```

### 6.2 平台三项(legacy 绝对阈值)

```
时序:最近强势日 ts(RPS60 进前 10%)
      → 至少 15 个交易日
      → 触线日 td = ts 之后首个满足 low ≤ MA100×1.03 且 MA100[k] > MA100[k−20]

平台深度   = 1 − min(low[ts:t]) / max(high[ts:t])        阈值 ≤ 0.352
平台缩量比 = mean(volume[ts:t]) / mean(volume[ts−60:ts−1])  阈值 < 0.80
平台收敛比 = mean(TR[td:t])     / mean(TR[ts−60:ts−1])      阈值 < 0.80

TR = max(high−low, |high−prev_close|, |low−prev_close|)     真实波幅,含跳空
平台信号:三条全中且收盘严格突破平台上沿 → 平台突破(研究)
          三条全中 → 平台观察;其余 → 无平台信号
```

**成交量用原始值,不做复权反调整**(前复权只调 OHLC)。

### 6.3 质量四因子

```
eligibility:  TTM净利率 > 0
              ROE > 0
              ROE同比变化:要求 ep_ttm > 0
              现金利润转换:要求 ep_ttm > 0 且 cfp_ttm > 0 且 转换率 > 0

顺序:先应用 eligibility → 对该因子当日有效横截面取 1%/99% 分位 → clip
      → 对缩尾后的值做升序百分位排名 → 四项等权平均
      → 任一缺失则整体缺失(不按剩余因子平均,不填零)

财务在公告日之后的第一个交易日生效,禁止未来回填。
```

### 6.4 周线

```
重采样:W-FRI,周收盘 = 该周最后一个可用交易日的收盘
取值:  「周标签日期 ≤ 观察日」的最后一行
        —— 周一至周四观察用上一已完成周;周五收盘观察用当周

正式二元:周线多头排列 = 周收盘 > MA20周 > MA60周

展示五态(有序判别,先命中优先):
  未知      → MA20周 或 MA60周 缺失
  多头趋势  → 周收盘 > MA20周 > MA60周
  突破启动  → 周收盘 ≥ MA20周 且 日线 ret_5 > 5%
  回踩修复  → 周收盘 ≥ 0.95 × MA60周 且 周收盘 < MA20周
  均线蓄势  → |周收盘 / MA20周 − 1| ≤ 5%
  弱势结构  → 其余
```

## 7. 六个已知的坑(都踩过)

1. **`resample("W-FRI")` 的空周**。春节/国庆整周无交易时会生成全 NaN 行,
   而 `rolling(60, min_periods=60)` **只要窗口里有一个 NaN 就整段返回 NaN**。
   13 年里十几个空周,足以把 MA60周 全打成 NaN。
   **修正:重采样后先 `dropna(how="all")`。**
2. **float32 存价格边界**。平台上下沿存成 float32、与 float64 收盘价比较时,
   在「打平」处会把**等于**误判成**突破**。**一律 float64。**
3. **弱断言会放过真 bug**。随机抽 (日期, 股票) 验无前视,1,500 次可能只命中几个事件,
   然后「通过」。**要从真实事件里抽样验证**,不要从全表随机抽。
4. **`rolling` 均值与重算均值的末位差**。`rolling(20).mean()` 与
   `np.mean(x[-20:])` 在末位可能差 1 ulp,导致 `收盘 > MA20` 在打平处翻一天,
   持续度差恰好 1/120。**这是无害假象,断言要留容差,不要按 1e-9 判。**
5. **当日收盘确认 + 当日收盘成交在实盘不可执行。** 回测须改为次日开盘或次日收盘;
   同时要处理涨跌停无法成交、跳空穿透止损、流动性约束。
6. **前复权锚点不同**。两边数据末日不同,绝对价格会差一个每只股票固定的倍数,
   **但比值型字段不受影响**。核对时先比比值,不要比绝对价格。

## 8. 必须留在交付物里的边界

- **平台信号是研究状态(WATCHLIST),不是买点。** 已知存在典型假突破:
  突破日 RPS 已回落、收盘位于当日振幅偏低位置、长上影、次日跌回上沿。
  在「当日 RPS / K 线质量 / 次日确认」等过滤完成前,只能作为事件池。
- **「案例展示分层_质量」「案例辅助标签_周线五态」不是任何正式规则的一部分**,
  命名上就要能看出来。
- **本模板是候选筛选与状态标记,不是买入指令,不构成投资建议。**

## 9. 一个经验值,供交叉核对时参考

在全市场 13 年面板上,**强确认(RPS60 ≥ 90)与任何平台信号的交集通常为 0**。

不是巧合,是**构造上互斥**:强确认要求股票正在强势拉升,
平台状态要求它已经回踩 20 周线并缩量走平 —— 一只股票不可能同时是这两个样子。

**「信号交叉表」页那一格若不为 0,先怀疑平台或分档的实现,而不是当成发现。**
